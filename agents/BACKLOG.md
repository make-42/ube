# Engine backlog: SearXNG engines to port to ube

Generated from SearXNG commit `a7128d5` (2026-11-14): `searx/engines/*.py` (253 modules) and `searx/settings.yml` (353 configured instances, 230 disabled and 91 inactive by default). Endpoints and quirks below were read from that code, not from memory. Where something could not be confirmed it says **verify**.

Read `agents/ENGINES.md` first: it explains the conventions, the engine *types*, and the traps. Pick the next engine from the top of the table that is not `done`.

## How the priority is computed

`score = 2*value + ease + reliability + unlock`, each 1 to 5 (unlock 0 to 2). Tiers: **P0** >= 18, **P1** 16-17, **P2** 13-15, **P3** 10-12, **P4** < 10.

- **value**: how useful the results are to a private metasearch (quality, uniqueness, coverage of the tab).
- **ease**: 5 = one documented JSON GET, 3 = HTML scrape or a small two-step, 1 = anti-bot / TLS fingerprinting / JS-literal parsing.
- **reliability**: how stable the upstream is (documented API and enabled-by-default upstream score high; captcha/token dances score low).
- **unlock**: tabs or instances that come almost free once this exists (Google `tbm` variants, Bing family, config-driven families).
- **effort**: S = under ~150 lines, M = a day, L = several iterations and live debugging.

Already ported (do not redo): `google` (pages), `duckduckgo` (pages, HTML endpoint), `docker hub` (pages, weight 0.3), `bing videos` (videos).

## Do not port

**Need an API key upstream:** every `*_api` engine above. Do not port keyed engines unless the human supplies a key via an env var; never hardcode keys (the Pexels key in SearXNG is a scraped site key, not a secret you should copy).
**Self-hosted / not a public service:** yacy, searxng instances, elasticsearch, meilisearch-style engines.
**Onion services:** ahmia, torch (need Tor routing).
**Blocked here:** Arch Wiki (see its row).
